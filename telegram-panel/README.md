# Telegram Panel — панель для нескольких операторов на одном аккаунте

Позволяет нескольким сотрудникам (операторам) переписываться из чатов
**одного** личного Telegram-аккаунта через собственный веб-интерфейс:

- админ назначает каждому оператору свой набор чатов;
- оператор видит только назначенные ему чаты и переписку в них;
- оператор **не может** увидеть username/телефон/id собеседника или чужие чаты —
  эти данные в принципе не передаются в его интерфейс (ограничение реализовано
  на уровне API, а не только скрыто в вёрстке);
- у оператора нет доступа к настройкам аккаунта — своего интерфейса, кроме
  списка назначенных чатов, у него просто не существует;
- админ видит все чаты и сообщения, может удалять сообщения и целые чаты,
  создавать/удалять операторов и включать/выключать им право отправки и
  удаления по каждому чату отдельно;
- **шаблоны ответов** — админ ведёт общую библиотеку заготовок, операторы
  вставляют их в сообщение в один клик;
- **очередь чатов** — админ может не назначать чат конкретному оператору,
  а положить его в общую очередь; любой оператор сам берёт чат в работу
  кнопкой «Взять в работу» (без гонки — конкретный чат достаётся только
  первому, кто нажал);
- **статистика по операторам** — количество отправленных сообщений
  (сегодня/всего) и число назначенных чатов на каждого.

## Архитектура

- Единственный компонент, который реально общается с Telegram, — бэкенд
  (Node.js + [GramJS](https://gram.js.org/), MTProto user-client с одной
  сессией вашего аккаунта).
- Операторы и админ работают только с этим бэкендом через свой логин/пароль
  (не имеющий отношения к Telegram) и обычный браузер.
- Список доступа "оператор → чаты" хранится в `data/db.json`.

## Демо-режим

Без учётных данных Telegram панель запускается в демо-режиме с тремя тестовыми
чатами и имитацией входящих сообщений — удобно, чтобы проверить логику ролей
и интерфейс до подключения реального аккаунта.

```bash
cd telegram-panel
npm install
cp .env.example .env      # задайте ADMIN_PASSWORD и JWT_SECRET
npm start
```

Откройте `http://localhost:3000`, войдите под `admin` / паролем из `.env`.

## Подключение реального аккаунта

1. Получите `api_id` и `api_hash` на https://my.telegram.org (My applications →
   API development tools).
2. Впишите их в `.env` (`TG_API_ID`, `TG_API_HASH`).
3. Один раз выполните:

   ```bash
   npm run login
   ```

   Скрипт запросит номер телефона, код из Telegram и пароль 2FA (если
   включён) — это стандартный вход в аккаунт, код вводите сами, скрипт его не
   запрашивает у меня и никуда не отправляет, кроме самого Telegram. В конце
   выведется `TG_SESSION` — впишите его в `.env`.
4. Перезапустите `npm start`. Панель подключится к вашему настоящему аккаунту
   и подтянет реальные диалоги.

**`TG_SESSION` — это фактически ключ доступа ко всему аккаунту**, как пароль.
Не публикуйте его, не коммитьте `.env` в git (уже добавлено в `.gitignore`).

## Деплой

GitHub Pages отдаёт только статику и не подходит для этого бэкенда — нужен
обычный сервер/VPS/PaaS (Render, Railway, свой сервер и т.п.), который держит
процесс `npm start` постоянно запущенным, желательно за HTTPS (например, через
reverse-proxy) — иначе логин-cookie и WebSocket будут ходить в открытом виде.

## Важно

- Используйте это только с ведома и согласия операторов и в рамках
  [условий использования Telegram](https://telegram.org/tos) и применимого
  законодательства. Инструмент разграничивает доступ *внутри вашей команды*
  (кто из сотрудников что видит) — он не предназначен для того, чтобы вводить
  в заблуждение людей, которые пишут в эти чаты, о том, с кем/с какой
  организацией они на самом деле общаются.
- Хранение переписки клиентов — это персональные данные; проверьте, что вы
  соблюдаете применимые требования по их защите и хранению.
